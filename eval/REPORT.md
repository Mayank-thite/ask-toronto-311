## Error analysis (7B, hand-labelled, one primary cause per miss)

| Cause | Misses | Questions |
|---|---|---|
| concept mapping | 4 | s15: searched request_type for 'missed collection' instead of topic = 'Missed collection'; m07: used topic 'Bins' plus a 'green bin' keyword; misses belong to 'Missed collection'; m09: searched for the exact phrase 'bin lid'; the city writes 'Bin Lid Damaged' and 'Repair or Replace Lid'; x15: searched request_type for 'missed collection' instead of the topic |
| copied example filter | 3 | r17: added a 2025 filter the question never asked for; m12: added a 2025 filter (and searched an exact phrase); x07: added a 2025 filter copied from the example it was adapting |
| aggregation logic | 3 | x03: filtered to Noise in WHERE, so every ward's share became 100%; x06: averaged requests per day per ward instead of averaging across wards; x11: computed previous minus current, so every change has the wrong sign |
| output shape | 3 | x10: listed the request types instead of counting them; x14: returned one row per day instead of the number of days; x20: returned one count per ward instead of the number of wards |
| wrapping range | 2 | t05: "11 pm to 5 am" written as BETWEEN 23 AND 5, which matches nothing; m10: "December to February" written as BETWEEN 12 AND 2 OR year = 2025 |
| decomposition | 2 | x02: ranked topics by total volume instead of by year-over-year change; x12: counted wards in the top 5 instead of summing their requests |
